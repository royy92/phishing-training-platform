# Governance

## Governance Model

The Phishing Awareness Training Platform follows the Benevolent Dictator For Life (BDFL) governance model.

At this stage, the project is maintained by a single maintainer who is responsible for guiding the project's direction, reviewing contributions, and making final decisions. Community feedback is encouraged and carefully considered, but the final decision rests with the maintainer to ensure the project remains focused and consistent with its goals.

## Decision Making

Before accepting any change, the maintainer considers whether it improves the platform, supports phishing awareness training, aligns with the project's direction, and maintains the project's security and stability.

New features are accepted only when they clearly support the project's mission and long-term goals, rather than simply being useful or technically interesting.

## Pull Requests and Reviews

All contributions are welcome and appreciated.

Every Pull Request is reviewed before it can be merged. Passing automated tests is important, but it is not the only requirement. A contribution should also:

- Align with the project's goals.
- Maintain code quality and readability.
- Follow the project's contribution guidelines.
- Avoid unnecessary complexity.

If a contribution does not fit the project's direction, it may be respectfully declined with an explanation.

Constructive feedback is provided whenever possible to help contributors improve their submissions.

## Project Priorities

The project follows these priorities when making development decisions:

1. Security before new features.
2. Stability and reliability before expanding functionality.
3. Simplicity and maintainability over unnecessary complexity.
4. Educational value for users above feature count.

The goal is to build a secure, reliable, and maintainable platform rather than adding features that do not directly support the project's mission.

## Future Governance

As the project evolves and the contributor community grows, additional maintainers may be appointed to assist with reviewing contributions and sharing project responsibilities.

Any future changes to the governance model will aim to preserve the project's mission while encouraging open and collaborative development.
